# TXMD — 다국어 TX 마크업 명세

TX 마크업(스킬 `tx-html-generator` 의 `MARKUP_SYNTAX.md`)에 **번역 줄**과 **동적 표**를 더한 상위 호환 문법.
`@` 줄이 없으면 기존 마크업과 100% 같다(기준 언어 ko 만). 파서: `parseTxmd()` (`src/markup/parser.ts`).
기존 마크업만 HTML 로 바꾸려면 `parseMarkup()` (원본 파이썬 파서와 같은 출력, 골든 테스트로 보증).

## 1. 번역 줄

```
@<언어코드> <번역 텍스트>
```

- 줄 맨 앞(들여쓰기 허용)의 `@en`, `@ja` … 뒤에 공백 하나 이상, 이어서 번역. **파서에 전달한 비기준 언어 목록(`langs`, 기본 `['en','ja']`)에 있는 코드만** 번역 줄로 인식한다. 그 외(`@example.com 으로…`, `@fr`)는 일반 텍스트.
- 번역 텍스트에도 마크업 인라인 문법(`**굵게**`, `[링크](url)`, `|!#-변수|`, `{변수}`)을 쓴다. 변환 결과는 문자열표에 인라인 HTML 로 저장된다.
- 번역 줄은 **번역 대상 블록 바로 뒤**에 붙인다. 같은 언어의 `@` 줄이 여러 개면 원문 줄 수와 같은 방식으로 `<br/>`(인용문은 `<br>`)로 이어진다.
- 번역이 없는 언어는 그 블록의 문자열이 비어 있다(미번역).
- 대상 없는 `@` 줄(구분선 뒤, 빈 줄 뒤 등)은 경고 후 무시.

### 블록별 위치

| 블록 | 번역 줄 위치 | 비고 |
|---|---|---|
| 제목 `# …` (h1~h3) | 제목 줄 바로 아래 | |
| 문단 | 문단 안(같은 빈 줄 구간)에 원문 줄 뒤 | 여러 줄 문단: 언어별로 `@en` 줄을 같은 줄 수만큼 |
| 인용 `> …` | 인용 줄들 바로 뒤. `> @en …` 도 허용 | |
| 목록 항목 | **바로 앞 항목**(중첩 포함, 직전 항목) 바로 아래 | 들여쓰기는 자유. 부모 항목의 번역은 자식 항목 앞에 둔다 |
| 가로형 표 헤더 | `{…}` 줄 바로 아래 `@en {A\| B}` (중괄호는 생략 가능) | 칼럼 수가 다르면 경고 후 보정 |
| 가로형 표 행 | 행(`- …`) 바로 아래 `@en - a\| b` (`-` 생략 가능) | 셀 단위 문자열 |
| 세로형 표 행 | 행 바로 아래 `@en - 헤더: 값` (`-` 생략 가능) | 구분자 규칙(파이프가 콜론보다 우선)은 원문과 동일, 언어마다 달라도 됨 |
| 콜아웃 제목 | 여는 줄 `[정보: 제목]` 바로 아래 | 제목이 없는 콜아웃이면 경고 후 무시 |
| 콜아웃 본문 블록 | 최상위와 같은 위치 규칙(문단·제목·목록·표·버튼·인용 각각 위 행 참조) | §4-A 참조 |
| 버튼 | 버튼 줄 바로 아래 `@en 레이블` (레이블만, URL·스타일은 공통) | 연속 버튼 그룹 안에서도 각 버튼 아래에 붙인다 |
| 수평선 | 없음 | |

### 예

```
# 배송 시작 안내
@en Your shipment is on its way
@ja 発送開始のお知らせ

안녕하세요, |!#-cust_nm|님!
@en Hello, |!#-cust_nm|!
@ja |!#-cust_nm|様、こんにちは。

[표: 세로형]
- 주문번호: |!#-order_no|
@en - Order No: |!#-order_no|
[/표]

[정보: 배송 추적]
@en Track shipment
실시간으로 확인하세요.
@en Check in real time.
[/정보]

[버튼, 배송 추적하기, https://t.com/|!#-tracking_no|, primary]
@en Track shipment
```

## 2. 문자열 단위와 ID

`parseTxmd()` 결과: `structure` + `strings` + `sourceHash` + `dynamicTables` + `variables` + `warnings`.

- 문자열 단위 = 블록(h1~h3 / p / li / th / td / 버튼 레이블 / 콜아웃 제목 / 인용의 p). 요소마다 `data-t="b001"`… (문서 순서 순번)이 붙고 `structure` 에는 **텍스트가 없다**. `strings["b001"] = { ko: "…", en: "…" }`.
- `li` 의 문자열은 자기 텍스트뿐이다. 중첩 목록은 구조에 남고, 합성할 때 문자열이 요소 **열린 태그 바로 뒤**에 삽입되므로 `<li>텍스트<ul>…</ul></li>` 가 복원된다.
- 버튼의 URL·스타일은 구조에 있으므로 언어 공통이다(URL 안의 `|!#-변수|` 포함).
- `sourceHash`: 번역 줄이 있던 문자열은 그 시점의 기준 원문 해시를 기록(`hashText`). 이후 `findStale()` 로 '번역 오래됨' 판정.
- 다시 파싱할 때는 `inheritIds(prev, next, baseLang)` 로 이전 프로젝트의 ID·번역을 이어받는다(LCS 정렬: 같은 블록은 같은 ID, 같은 자리에서 원문이 바뀐 블록은 ID 유지+오래됨, 새 블록은 새 ID).
- `parseTxmd` 는 기본으로 `<main>` 으로 감싸지 않는다(`wrapMain: true` 로 켤 수 있음). `[헤더]` 마커는 `includeHeader` 플래그로만 반환한다.

## 3. 동적 표 (서버가 tbody 행을 생성)

```
[표: 가로형, 동적: orders]
{상품명| 수량| 금액}
@en {Item| Qty| Amount}
- {{name}}| {{qty}}개| {{amount}}원
@en - {{name}}| {{qty}} pcs| {{amount}} KRW
@var name 상품명
@var qty 수량
@sample name=무선 이어폰| qty=2| amount=90,000
@sample name=보조배터리| qty=1| amount=32,000
[/표]
```

- 선언: 여는 줄에 `, 동적: <표id>` (표 id 는 영문·숫자·`_`·`-`). **가로형만** 지원(세로형에 쓰면 경고 후 정적 표).
- 데이터 행(`- …`)은 **행 템플릿 1개**만 쓴다(2개 이상이면 경고, 첫 행만). 줄무늬·합계·빈 목록 변형은 없다.
- 행 변수는 `{{name}}` (영문·숫자·`_`·`.`·`-`·한글). 본문 치환자 `|!#-name|`·단일 중괄호 `{name}`(→ `|!#-name|` 자동 변환)과 **별개 체계**이며 이름이 겹치면 안 된다(`findVariableConflicts`).
- 행 템플릿 안 고정 문구(`개`, `pcs`)는 번역 대상이다. `@en` 번역 줄에도 같은 `{{변수}}` 를 모두 써야 한다(빠지면 경고).
- `@var <이름> <설명>`: 변수 설명(선택). `@sample k=v| k=v`: 예시 행(여러 줄 = 여러 행, 미리보기 전용). 이 두 줄은 동적 표 안에서만 의미가 있고 언어 코드와 무관하게 항상 인식한다(그래서 `sample`, `var` 는 언어 코드로 쓸 수 없다).

### 모델·합성 결과

- `structure` 의 표: `<tbody data-rows="orders"></tbody>`. 행 템플릿은 `dynamicTables[i] = { id, rowStructure, vars, sampleRows }`.
  - `rowStructure`: `<tr><td data-t="b007"></td>…</tr>` — 본문과 **같은 ID 체계·같은 `strings` 표**에 합류한다. 이유: 언어별 행 템플릿이 필요한데, 별도 저장소를 만들면 문자열 그리드·오래됨 판정·ID 이어받기·검사를 모두 이중 구현해야 한다. ID 가 하나의 표에 있으면 이 기능들이 그대로 동작한다.
  - `vars`: 행 템플릿에서 추출한 `{{변수}}`(+`@var` 설명, 첫 예시 행 값을 sample 로).
- `composeForSend(src, lang)`: `<tbody>|!#-rows_orders|</tbody>` — tbody 안에는 표식 치환자 하나뿐. 행 템플릿·예시 행·`data-*` 는 발송 HTML 에 들어가지 않는다(서버가 `|!#-rows_orders|` 를 `<tr>…</tr>` 연속 문자열로 교체).
- `composePreview(src, lang)`: 같은 표를 예시 행으로 채운 tbody (값은 HTML 이스케이프, `data-t` 유지로 클릭 편집 가능). 예시 행이 없으면 표식 치환자 그대로.
- 번들 내보내기(P3)에는 `dynamicTables`(행 템플릿 언어별 합성 결과 포함)를 별도로 싣는다(구현됨: `buildBundle`).

## 4-A. 콜아웃 본문 (확장)

`[정보|경고|강조(: 제목)]` … `[/…]` 사이에 **최상위와 같은 블록 문법**을 쓴다(같은 파서 `parseBlocks` 를 공유). 규격 출처: `MARKUP_SYNTAX.md` 「콜아웃 내 마크다운/테이블」「엣지 케이스: 중첩된 구조」와 `sample/sample.html` 4절의 콜아웃 구조(`div.callout > h3 + p/ul/ol/table/p>a.btn`). 출력은 sample.html 과 같은 구조이며(`__golden__/handwritten/` 발췌 골든) `<main>` 중첩 버그는 따르지 않는다.

| 본문 요소 | 문법 | 출력 |
|---|---|---|
| 문단 | 연속 줄(`<br/>` 로 이어짐), 빈 줄로 문단 분리 | `<p>` |
| 소제목 | `### x` (h3). **`#`·`##` 줄은 콜아웃을 자동 종료**(경고) | `<h3>` |
| 목록 | `- x` / `1. x`, 들여쓰기로 중첩 | `<ul>`/`<ol>` |
| 표 | `[표: 가로형]…[/표]`, `[표: 세로형]…[/표]` | `table.table-horizontal/vertical` |
| 버튼 | `[버튼, 레이블, URL, 스타일]` (연속하면 그룹) | `<p><a class="btn …">` / `<p class="btn-group">` |
| 인용 | `> x` | `<blockquote><p>` |
| 구분선 | `---`/`***`/`___` | `<hr>` |

경계 규칙(불분명했던 부분을 이렇게 정했다):
- **문단 ↔ 블록 경계**: 문단은 빈 줄 없이도 목록(`-`,`*`,`1.`)·표(`[표:`)·버튼(`[버튼,`)·인용(`>`)·`#`·구분선·콜아웃 시작 줄에서 끝난다(최상위 문단과 같은 규칙).
- **콜아웃 끝 탐색이 먼저**다: 파서는 `[/종류]` (또는 `#`/`##` 줄, 파일 끝)까지를 본문으로 잘라낸 뒤 본문을 해석한다. 그래서 본문 안 표의 `[/표]` 가 없으면 **콜아웃 끝에서 표가 닫히고** 경고가 한 번 난다.
- **콜아웃 안 콜아웃**: 지원하지 않는다. 안쪽 콜아웃은 `<blockquote><p>`(내용은 `<br>` 로 이어짐)로 낮추고, **`parseTxmd` 경로에서만** 경고한다(`parseMarkup` 은 원본 stderr 골든 보존을 위해 경고 없음). 안쪽 `[/종류]` 까지가 인용이고, 바깥 콜아웃은 바깥 종류의 첫 `[/종류]` 에서 끝난다(같은 종류를 중첩하면 안 된다).
- 내용이 빈 안쪽 콜아웃(`[경고]`+`[/경고]`)은 통째로 건너뛴다.
- **동적 표(`동적: id`)는 콜아웃 안에서 지원하지 않는다**(결정): 경고 후 정적 표로 처리, `dynamicTables` 에 등록되지 않는다. 사유: 동적 표는 `tbody` 를 서버 표식 치환자로 대체하는 구조인데, 콜아웃 안 위치·행 템플릿 ID 이어받기 규칙을 별도로 정의해야 하고 현재 요구가 없다. 필요하면 콜아웃 밖에 둔다.
- 경고의 `(line N)` 은 콜아웃 본문 안에서도 원문 기준 줄 번호다.

### 번역 줄 (콜아웃 본문)

규칙은 §1 과 같다 — 번역 줄은 **바로 앞 블록**에 붙는다. 콜아웃에서만 추가로: 여는 줄 바로 아래의 `@xx` 연속 줄은 **제목** 번역(제목 없는 콜아웃이면 경고 후 무시). 본문 문단·목록 항목·표 셀(`@en - a| b`)·버튼 레이블·인용 각각이 **1개 문자열**이며 `data-t` 를 받는다. ID 는 문서 순서(제목 → 본문 위→아래). `composeForSend` 로 합성하면 data-t 가 제거되고, `decompose()` 로 다시 분해해도 같은 구조·문자열이 나온다(왕복 테스트 `extended.test.ts`).

```
[정보: 연동 확인]
@en Check before linking
시작 전에 **준비**하세요.
@en Prepare **first**.

- 계정
@en Account

[표: 세로형]
- 업체: CJ
@en - Carrier: CJ
[/표]

[버튼, 추적, https://t.com/|!#-no|, primary]
@en Track
[/정보]
```

## 4-B. 취소선 (확장)

`~~text~~` → `<del>text</del>` (문자열 단위 규칙은 그대로: 블록 단위 + 인라인 `strong/em/del/a/br`). 인식 조건:
- 안쪽 양끝은 공백·`~` 가 아니어야 한다(`a ~~ b ~~ c`, `~~~x~~~` 는 그대로 둠). 단일 `~`(`월~금`)·닫힘 없는 `~~` 는 일반 텍스트.
- **보호**: `|!#-변수|`, `{{행 변수}}`, 링크 URL `[x](url)`, **본문 속 맨 URL(`http(s)://…` 공백/`]`/`)` 전까지)** 안의 `~ _ *` 는 취소선·강조로 해석하지 않는다(변수 이름·URL 에는 `~` 가 올 수 없다고 보고, URL 은 통째로 보호).
- 다른 서식과 중첩 가능(`~~**굵게**~~`). 합성 시 `sanitizeInline` 허용 목록에 `del` 포함.
- 한계: 맨 URL 보호는 공백·`< > [ ] )` 에서 끝난다. 괄호가 든 URL 은 `)` 앞까지만 보호되므로 마크다운 링크 `[x](url)` 로 쓸 것.

## 4-C. 링크는 항상 새 창 (자동 보장)

버튼(`[버튼, …]` → `a.btn`)과 인라인 링크(`[x](url)`, 맨 URL 포함)는 **작성자가 `target` 을 쓰지 않아도** 합성 결과에서 항상 `target="_blank" rel="noopener noreferrer"` 를 가진다.

- 보장 위치: `composeLang`(→ `composeForSend`·`composePreview`, 행 템플릿 합성 포함). 구조·문자열 원본과 파서 출력은 그대로라 편집·번역·ID 이어받기·`sourceHash` 에 영향이 없다. 구현은 `links.ts` 의 `ensureLinkTargets`(멱등).
- 콜아웃 안 버튼·버튼 그룹·동적 표 행 템플릿 안 링크(`{{var}}` href 포함)·셸 로고 링크 모두 같다.
- 문자열에 이미 `target="_self"` 등이 있으면 `_blank` 로 바꾸고, `rel` 이 있으면 `noopener noreferrer` 를 병합한다.
- **제외**: `mailto:` `tel:` `sms:` 와 `#앵커` 는 붙이지 않는다(앱 호출·같은 문서 이동이라 새 창이 무의미하거나 해롭다). `href` 없는 `<a>` 도 그대로. 치환자(`|!#-url|`)·`{{var}}`·상대 경로·`http(s)://` 는 붙인다.
- 번들 검증(`verifyBundle`)이 이 규칙을 검사한다(docs/bundle-schema.md §2).

## 4. 문법 메모·알려진 제한

- 콜아웃 본문·취소선은 원본 파이썬 파서에 없던 확장이다(§4-A, §4-B). 확장은 `parseMarkup`·`parseTxmd` 양쪽에 적용되며, 원본이 지원하던 입력의 출력은 골든(`__golden__/expected`, 불변)으로 보증한다.
- 단일 열 가로형 표 헤더 `{이름}` 은 단일 중괄호 변수 변환에 걸려 `|!#-이름|` 이 되어 표가 깨진다(원본 동일). 열이 1개인 가로형 표는 쓰지 말 것(세로형 사용). 필요하면 파서 개선 필요.
- 문자열은 허용 인라인 태그(strong/em/a/br + 치환자)만 유지: 합성 시 그 외 태그는 제거하고 경고(`inline-tag-removed`).
- 원본 파서와의 의도적 차이 목록은 `parser.ts` 상단 주석 참조(변수·URL 안의 `_` 오인 수정, 중첩 순서 목록 무한루프 수정 등).

## 5. 스킬 개정용 요약 (P8: tx-html-generator SKILL.md / MARKUP_SYNTAX.md 가 따를 문법)

스킬 문서에 반영·유지할 것:
1. **콜아웃 본문**: 문단, `###` 소제목, 순서/비순서 목록(들여쓰기 중첩), 세로형·가로형 표(`[표:…]…[/표]`), 버튼(연속 줄 = 그룹), 인용(`>`), 구분선(`---`)을 쓸 수 있다. 표·버튼은 앞뒤에 빈 줄을 두는 것을 권장(필수 아님).
2. **콜아웃 금지/주의**: 콜아웃 안 콜아웃 불가(인용으로 낮아지고 경고), 본문 안 `#`·`##` 제목은 콜아웃을 끝낸다(`###` 만 사용), 같은 종류 중첩 불가, 닫는 `[/종류]` 필수, 동적 표 불가(경고 후 정적 표). 안쪽 표의 `[/표]` 도 닫을 것.
3. **취소선** `~~text~~` 를 인라인으로 쓸 수 있다(`MARKUP_SYNTAX.md` 「텍스트 강조」에 이미 적혀 있었으나 원본 파서는 지원하지 않았음 — 이제 지원).
4. **번역 줄**(`@en`/`@ja`, 선택): 번역할 블록 바로 아래에 붙인다. 콜아웃 안의 문단·목록 항목·표 행·버튼·인용에도 동일. 콜아웃 여는 줄 바로 아래는 제목 번역. 번역 줄이 없으면 기존 마크업과 같다.
5. 스킬 예시 중 `MARKUP_SYNTAX.md` 의 `{이름, 이메일, 전화}`(콤마 구분 헤더)·`[표: 가로형]` 콤마 행 예시는 파서가 파이프(`|`) 구분만 해석하므로 **문서 예시를 파이프로 고칠 것**(원본 문서의 불일치, 이번 확장 범위 밖이라 파서는 그대로).
6. 출력 구조는 `sample/sample.html` 과 같다(`div.callout.callout-{info|warn|accent} > h3 + 본문 블록`). 템플릿의 `callout-danger` 는 마크업 종류에 없다(정보/경고/강조 → info/warn/accent).
7. **머리말(front matter, 선택)**: 파일 맨 첫 줄을 `---` 로 시작해 `kind`(mail|notice)·`name`·`templateCode`·`subject.ko/en/ja` 를 `key: value` 로 적고 `---` 로 닫으면, 앱의 `.txmd 불러오기` 가 유형·이름·코드·제목까지 채워 새 프로젝트를 만든다(§6). 머리말이 없으면 본문만 읽는다.

## 4-D. 공지 유형(kind: notice)에서의 사용

`+ 초안` 에서 유형을 **공지**로 만들면 같은 문법(`@en`/`@ja` 번역 줄 포함)을 쓰되 다음이 다르다. 출력 규격은 `docs/notice-format.md`.

- **셸 없음**: 로고 헤더·푸터·표 래퍼를 붙이지 않는다(`planDraft` 가 `wrapShell` 을 건너뜀). `[헤더]` 마커는 의미가 없다.
- **치환자 금지**: `|!#-x|`·`{{x}}` 는 만들기 경고, 검사 오류(`notice-placeholder`)로 내보내기를 막는다.
- **동적 표 금지**: `[표: 가로형, 동적: id]` 는 만들기 오류. 같은 표는 `[표: 가로형]` 정적 표로 쓴다.
- 링크는 §4-C 와 같이 항상 `target="_blank" rel="noopener noreferrer"` 로 나온다.
- 제목은 초안이 아니라 프로젝트의 "공지 제목"(ko/en/ja)에서 온다. 출력 구역마다 `<!-- tx:title … -->` 로 들어간다.

## 6. 머리말(front matter) — `.txmd 불러오기`

스킬이 만든 `.txmd` 파일 1개로 새 프로젝트를 만들 때(프로젝트 목록의 `.txmd 불러오기`) 파일 앞에 머리말을 둘 수 있다. 없으면 본문만 읽는다(`+ 초안` 과 같은 동작, 이름은 본문 첫 제목).

```
---
kind: mail
name: 배송 시작 안내
templateCode: SHIP_START
subject.ko: 배송이 시작되었습니다
subject.en: Your shipment is on its way
subject.ja: 発送を開始しました
---
# 배송이 시작되었습니다
…(이후 본문 = 위 문법 그대로)
```

- 파일 **맨 첫 줄**이 `---`, 이후 `---` 한 줄로 닫는다(BOM·CRLF 허용). 닫는 줄이 없으면 경고하고 전체를 본문으로 읽는다.
- 한 줄에 `key: value`: 첫 `:` 뒤를 trim 한다(따옴표 불필요, 값에 `:`·URL 가능). 빈 줄과 `#` 로 시작하는 줄은 무시. 중첩 없음.
- 키: `kind`(`mail`|`notice`, 생략 시 mail, 다른 값은 경고 후 mail — 이 값에 한해 줄 끝 `# 설명` 허용), `name`(프로젝트 이름, 생략 시 본문 첫 제목), `templateCode`(선택), `subject.ko`·`subject.en`·`subject.ja`(언어별 제목, 일부만 가능). 언어는 ko·en·ja 고정. 알 수 없는 키는 경고 후 무시.
- 머리말은 본문 파서에 넘기기 전에 제거되므로, 본문 파서 경고의 `(line N)` 은 **머리말을 뺀 본문 기준**이다.
- 가져오기 실패(빈 본문·공지의 동적 표 등)는 프로젝트를 만들지 않고 이유를 토스트로 알린다. 경고(머리말·본문·공지의 치환자)는 만든 뒤 토스트로 알린다.
- **kind 별 차이**: mail 은 메일 제목(`project.subject`)이 되고 셸(로고·푸터)이 붙는다. notice 는 셸이 없고 치환자·동적 표를 쓸 수 없으며(§4-D), 제목은 출력 구역마다 `<!-- tx:title … -->` 주석으로 나온다.
