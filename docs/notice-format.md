# 공지 HTML 형식 (kind: notice)

공지 유형 프로젝트의 출력 규격. 메일(번들 JSON)과 달리 **HTML 파일 하나**이며, 사람이 언어별 구역을 복사해 공지 시스템 폼에 붙여 등록한다(공지는 언어마다 별개 게시물).

## 1. 사용 방법

1. 앱 상단 `+ 초안` → 유형 **공지** 선택(기본은 메일, 만든 뒤 유형 변경 불가) → 초안(.txmd)과 `@en`/`@ja` 번역 줄 입력 → 프로젝트 만들기.
2. 제목(공지 제목)을 ko/en/ja 로 입력한다(블록 목록 맨 위 "공지 제목").
3. 우측 [내보내기] 패널
   - **공지 HTML 저장**: `notice_<이름>.html` (이름 = 템플릿 코드, 없으면 프로젝트 이름)
   - **공지 HTML 복사**: 파일 전체
   - **{lang} 구역 복사**: 해당 언어 본문 HTML 만(구역·제목 주석 제외) — 공지 폼 본문에 붙인다
   - **{lang} 제목 복사**: 한 줄로 접은 제목 원문(이스케이프 없음) — 공지 폼 제목에 붙인다
4. 검사 오류가 있으면 저장·복사가 막힌다(강제 체크로만 가능).

## 2. 파일 구조

```
<!-- tx:lang ko -->
<!-- tx:title [공지] 시스템 점검 &#45;- 10/20 안내 -->
<h1 style="…">…</h1>
<p style="…">…</p>
<!-- /tx:lang ko -->

<!-- tx:lang en -->
<!-- tx:title Maintenance … -->
…
<!-- /tx:lang en -->
```

- 구역은 `project.langs` 순서(기본 ko, en, ja). 구역 사이에 빈 줄 하나, 파일 끝은 개행.
- 구역 시작 `<!-- tx:lang {lang} -->`, 끝 `<!-- /tx:lang {lang} -->`. 언어 코드는 `[A-Za-z0-9_-]` 외 문자를 `_` 로 바꾼다.
- 구역 맨 앞(시작 주석 바로 아래)에 제목 주석 `<!-- tx:title {제목} -->` 한 줄. 제목 = 해당 언어의 `project.subject[lang]`.
- 구역 내용은 **본문 조각**뿐이다: 로고 헤더·푸터·600px 표 래퍼(셸)·`<main>`·`<html>`/`<body>` 없음. 클래스 `mail`/`mail-*`·`data-t`·`data-tx-shell` 도 없다(검사로 확인).
- 구역 내용에는 주석이 없다(문자열의 주석은 합성 단계에서 제거됨). 그래서 `<!-- … -->` 경계는 모호하지 않다.
- `tx:lang` 구역을 다시 읽는 코드: `parseNoticeHtml()` (`src/project/notice.ts`).

## 3. 제목 주석 이스케이프

제목은 한 줄 텍스트로 접은 뒤(모든 공백·개행·제어 문자 → 공백 1개, 앞뒤 trim) 주석을 깨지 않게 바꾼다(`escapeCommentText`).

| 입력 | 변환 | 이유 |
|---|---|---|
| `&` `<` `>` | `&amp;` `&lt;` `&gt;` | `-->`·`--!>`·`<!--` 이 생길 수 없게 한다 |
| 뒤에 `-` 가 오는 `-` | `&#45;` | `--` 연속 금지(`--` → `&#45;-`, `---` → `&#45;&#45;-`) |

- 주석 앞뒤는 항상 공백(`<!-- tx:title ` … ` -->`)이라 제목이 `-` 로 끝나거나 `>`·`->` 로 시작해도 안전하다.
- 단일 하이픈·한글·날짜(`2026-10-20`)는 그대로다.
- 되돌리기는 `unescapeCommentText`(한 번에 치환: `&amp;#45;` 도 정확히 복원). 사람이 읽는 용도로는 **제목 복사** 버튼(이스케이프 없는 원문)을 쓴다.
- 언어 코드도 같은 이유로 안전한 문자만 쓴다.

## 4. 인라인 프로파일 (web)

- 엔진의 `web` 프로파일로 인라인한다: **font-family 를 내보내지 않아** 호스트 페이지 폰트를 상속하고, 조상과 같은 상속 값(글자 크기·색 등)은 다시 적지 않는다.
- 공지 렌더 중에만 임시 래퍼 `<div class="notice">` + `NOTICE_CSS`(`.notice` 기본 14px/25px/`--body`, 첫 자식 margin-top 0; template.css 의 `.mail` 규칙과 같은 값 — 단위 테스트가 대조)를 두고, 인라인 뒤 래퍼를 **벗긴다**. template.css 는 바꾸지 않으므로 메일 결과에 영향이 없다.
- 본문 요소(h1·p·ul·td·버튼 등)는 자기 글자 크기·색·줄 높이를 직접 선언하므로 래퍼를 벗겨도 본문이 깨지지 않는다. 래퍼에서만 오던 값(14px·25px·색)은 각 문단·목록·표 셀이 선언한 값으로 남는다.
- 호스트 페이지의 폭·여백·배경은 호스트가 정한다(출력에 폭 제한이 없다). 표는 `width: 100%`.

## 5. 링크

- 모든 `<a href>` 는 `target="_blank" rel="noopener noreferrer"` 를 가진다(`mailto:`·`tel:`·`sms:`·`#앵커` 제외). 합성 단계(`composeLang`)에서 보장하고, 인라인 뒤 다시 확인해 빠졌으면 복구하며 경고(`link-target-restored`)를 남긴다.
- 검사 오류 `notice-link-target`: 출력에 보장이 빠진 링크가 남은 경우.

## 6. 치환자·동적 표 금지

- `|!#-x|` 와 `{{x}}` 는 공지에 남으면 **검사 오류** `notice-placeholder`(구조·문자열·제목·출력 모두 검사). 내보내기가 막히고, [강제 내보내기] 체크로만 나온다.
- 동적 표는 쓸 수 없다. 초안 단계(`analyzeDraft`)에서 `[표: …, 동적: id]` 선언이 있으면 **만들기 오류**(조용히 정적 표로 바꾸지 않는다 — 의도와 다른 결과를 막기 위해). 프로젝트에 동적 표가 있으면 검사 오류 `notice-dynamic-table`.
- 초안의 치환자는 만들기를 막지 않고 경고만 한다(만든 뒤 검사 오류).

## 7. 검사 규칙 요약 (`validateProject`, kind 분기)

공통: `untranslated`(제목 포함 미번역), `stale-translation`(경고), `inline-tag-removed`(경고).
공지 전용 오류: `notice-placeholder`, `notice-dynamic-table`, `notice-shell`(구조에 셸), `notice-leftover`(출력에 셸·`mail` 클래스·`data-t`·주석), `notice-link-target`.
공지에서 건너뛰는 메일 규칙: 언어 간 치환자 집합·표식 형식·동적 표·Gmail 102KB.

## 8. 저장·재편집

- 재편집 원본은 **앱 저장(IndexedDB)** 뿐이다. 공지 HTML 에 source 를 넣지 않고 JSON 번들도 만들지 않는다(`exportBundle` 은 공지를 거부).
- `kind` 필드가 없는 레코드·번들 source 는 메일로 읽는다(마이그레이션 없음). 번들 불러오기는 항상 메일 프로젝트로 복원한다.
