# TracX Logis 다국어 템플릿(.txmd) 생성기

메일 템플릿과 공지를 **하나의 `.txmd` 파일**로 만든다. 한국어 원문을 기준으로 영어·일본어 번역 줄(`@en`/`@ja`)을 **Claude 가 직접 작성**해 같은 파일에 넣고, 머리말(제목·이름·종류)을 맨 위에 붙인다. 사용자는 이 파일을 앱에서 불러와 프로젝트를 만들고(번역 편집·인라인 CSS 변환·내보내기는 앱이 한다), 스킬은 확인용 **언어별 미리보기 HTML** 도 함께 만든다.

| 산출물 | 용도 |
|---|---|
| `<이름>.txmd` | **주 산출물.** 앱 '프로젝트 > .txmd 불러오기' 로 읽는다 |
| `<이름>_preview/preview_ko.html` `preview_en.html` `preview_ja.html` | 언어별 미리보기(보조). 메일은 로고 헤더·푸터·600px 래퍼 포함, 공지는 셸 없는 본문 조각. **발송·게시용이 아니다** |

## 종류 결정: 메일 / 공지

| | 메일 (`kind: mail`, 기본) | 공지 (`kind: notice`) |
|---|---|---|
| 셸(로고·푸터·표 래퍼) | 앱이 붙임(본문에 쓰지 않음) | 없음 |
| 치환자 `\|!#-x\|`·`{x}` | 가능(제목 포함) | **금지** |
| 동적 표 `[표: 가로형, 동적: id]` | 가능 | **금지**(정적 표로) |
| 제목 | `subject.*` = 메일 제목 | `subject.*` = 공지 제목 |
| 언어 | 한 메일에 ko/en/ja 문자열 | 언어마다 별개 게시물(앱이 구역으로 내보냄) |

사용자가 종류를 말하지 않았으면 **반드시 묻는다**("메일 템플릿인가요, 공지사항인가요?").

## 실행 프로세스

스크립트 위치: `/mnt/skills/user/tx-html-generator/scripts/` (이하 `$S`). 작업 파일은 `/home/claude/`, 산출물은 `/mnt/user-data/outputs/`.

### 1. 요구 파악

모자란 것만 묻는다(자명한 것은 묻지 않는다).
- 종류(메일/공지), 프로젝트 이름, (메일) 템플릿 코드(`templateCode`, 선택), 제목(ko).
- 내용 요지, 표·버튼·링크(URL)·강조할 안내, 톤.
- **메일이면 치환자 목록**: 이름(`cust_nm` 등)과 쓰이는 자리. 이름은 사용자와 정한다. 목록 형태의 반복 행(주문 상품 등)이 있으면 **동적 표**를 쓸지 확인한다(`@sample` 예시 값도 받는다).
- 번역할 언어는 기본 ko·en·ja 세 개. 고유명사·용어 표기(회사명·서비스명)가 정해져 있으면 받는다.

### 2. 한국어 초안 승인 (승인 전 .txmd 생성 금지)

`references/MARKUP_SYNTAX.md` 문법으로 **한국어 마크업 초안만** 사용자에게 보여준다(머리말 포함, 번역 줄 없이). 구조(제목·표·콜아웃·버튼)·문구·치환자·링크를 확인받고 수정한다.
- 사용자가 이미 완성된 마크업(또는 `.txmd`)을 줬다면 문법을 점검해 바로 3단계로 간다. 번역이 이미 있는 부분은 존중하고 빈 언어만 채운다.
- 작성 규칙: `- 항목: 값` 형태의 정보 나열은 세로형 표로, 버튼 스타일은 명시(자동 결정은 한국어 레이블 기준), 열이 1개인 가로형 표 금지.

### 3. .txmd 생성 (번역 포함)

승인된 초안에 **`@en`/`@ja` 번역 줄**을 채우고 머리말에 `subject.ko/en/ja` 를 넣어 `/home/claude/<이름>.txmd` 로 저장한다. 번역은 외부 도구 없이 Claude 가 직접 쓴다.

**번역 규칙**
- ko 원문이 기준이다. 뜻을 덧붙이거나 빼지 않는다(법적·금액·일정 문구는 특히).
- **치환자 `|!#-x|` 는 이름·철자 그대로** 보존한다(번역·삭제·추가 금지, 위치만 어순에 맞게 이동 가능). `{{x}}`(동적 표 행 변수)도 마찬가지. 모든 번역에 원문과 같은 집합이 있어야 한다.
- **URL 은 바꾸지 않는다.** 링크 텍스트만 번역한다. 버튼은 레이블만 번역한다.
- 고유명사(TracX Logis·택배사명·서비스명·상품명)는 원문 표기를 유지하거나 사용자 용어집을 따른다.
- 영어는 간결한 비즈니스 영어, 일본어는 です・ます調와 `様`. 날짜·금액은 해당 언어 관용으로(`10월 20일` → `Oct 20` / `10月20日`, `원` → `KRW` / `ウォン`) 단, 숫자 값은 그대로.
- 서식(`**굵게**`, `~~취소선~~`, 링크)과 문단·목록·표 구조를 원문과 같게 유지한다. 칸 수·줄 수가 원문과 같아야 한다.
- 제목(`subject.*`)과 본문 `# h1` 은 별개이지만 같은 취지로 번역한다(메일 제목은 치환자 포함 가능).
- **번역 줄은 대상 블록 바로 아래, 빈 줄 없이.** 위치 규칙은 MARKUP_SYNTAX.md 2절.

**머리말**(파일 맨 위, `---` 로 열고 닫음. 한 줄 `key: value`)

```
---
kind: mail
name: 배송 시작 안내
templateCode: SHIP_START
subject.ko: 배송이 시작되었습니다
subject.en: Your shipment is on its way
subject.ja: 発送を開始しました
---
```

`kind` = `mail`|`notice`(생략 시 mail), `name` = 앱에 보이는 프로젝트 이름, `templateCode` = 선택(메일). **줄 끝 주석을 붙이지 않는다**(값에 섞여 버린다). `subject.*` 언어는 ko·en·ja 만. 완성 예시는 `references/example.md`.

### 4. 검증 + 미리보기

```bash
cd /mnt/skills/user/tx-html-generator/scripts
python3 tx_generate.py /home/claude/<이름>.txmd \
  --normalize /mnt/user-data/outputs/<이름>.txmd \
  --preview-dir /mnt/user-data/outputs/<이름>_preview
```

- 종료 코드 0 = 통과(경고는 있을 수 있음), **1 = 오류**(고치고 다시 실행 — 오류가 남은 파일을 전달하지 않는다), 2 = 입력/실행 오류.
- 오류(`unclosed`·`placeholder-mismatch`·`notice-placeholder`·`notice-dynamic-table` 등)는 반드시 수정. 경고(`untranslated`·`link-changed`·`placeholder-moved` 등)는 하나씩 의도 확인 — 의도가 아니면 고친다. 코드 표는 MARKUP_SYNTAX.md 10절.
- `--normalize` 는 정규화본(LF·공백 정리·머리말 표준 순서)을 저장한다. 본문 의미는 바뀌지 않는다.
- 미리보기는 번역이 빠진 블록을 ko 문장으로 채워 보여 주므로(`--no-fallback` 으로 끌 수 있음) 누락은 **검증 경고로 확인**한다.
- 필요하면 `--strict`(경고도 실패), `--json`(기계 판독), `--langs ko,en`(언어 제한).

사용자 안내 문구(항상 포함):
- **앱에서 '프로젝트 > .txmd 불러오기' 로 이 `.txmd` 를 불러오면** 프로젝트(이름·제목·번역)가 만들어집니다. 머리말이 이름·제목·종류를 채웁니다.
- 미리보기 HTML 은 확인용이며 발송/게시용이 아닙니다(메일의 인라인 CSS 변환·내보내기는 앱에서 합니다).
- 번역은 제가 작성한 초안이니 원어민/담당자 검수를 권장합니다. 앱에서 번역을 이어서 편집할 수 있습니다.
- 파일 이름은 영문 소문자·숫자·`-`/`_` 로 정한다(templateCode 가 있으면 그것을 소문자화, 없으면 이름의 영문 요약).

## 하지 말 것

- 한국어 초안 **승인 전에 번역·`.txmd` 생성 금지**.
- **공지(`kind: notice`)에 치환자(`|!#-x|`, `{x}`, `{{x}}`)·동적 표 금지.** 필요한 값은 본문에 직접 쓴다. 공지 제목에도 치환자 금지.
- 메일 셸(로고·푸터·600px 표)·`<html>` 을 `.txmd` 본문에 직접 쓰지 않는다. `[헤더]` 마커도 쓰지 않는다. 원시 HTML 은 이스케이프되어 글자로 보인다.
- 번역에서 치환자·URL·고유명사 변경/누락 금지. `@en`/`@ja` 외의 언어 코드(`@fr`, `@jp`)를 쓰지 않는다.
- 번역 줄 앞에 빈 줄을 두지 않는다(대상 없는 줄이 되어 무시됨). 콜아웃 안 콜아웃, 콜아웃 본문 `#`·`##`, 닫는 태그(`[/정보]`·`[/표]`) 누락 금지.
- 머리말 줄 끝에 `# 주석`을 붙이지 않는다. 머리말의 `subject.*` 언어는 ko·en·ja 만.
- 검증 오류가 남은 파일을 "완성"으로 전달하지 않는다. 검증을 건너뛰지 않는다.

## 보조 사용(호환)

```bash
# 본문 HTML 만(원본 호환 파서, 번역 줄 무시)

```

## 참조

- `references/MARKUP_SYNTAX.md` — 문법 전체(번역 줄 위치, 콜아웃 본문, 취소선, 동적 표, 머리말, 검증 코드)

- `assets/` — 미리보기용 `template.css`(앱 `src/styles/template.css` 사본)·`template_base.html`·`logo_tx.png`
- `tests/` — 스킬 실행에는 불필요(회귀·앱 파서 대조 테스트). 실행: `python -I tests/test_parity.py`

## 에러 처리

- 검증 메시지를 그대로 읽고 해당 블록을 고친 뒤 재실행한다(줄 번호는 머리말을 뺀 본문 기준).
- 문법이 헷갈리면 MARKUP_SYNTAX.md 를 읽는다. 파일을 못 읽으면(UTF-8 아님 등) 사용자에게 알린다.
